Vina Grid Box

Author: Ayan Bhowmik
Contact: ayan.bhowmik.bd@gmail.com
Version: 1.9.1
License: MIT

ChimeraX Vina Grid Box is a visualization and search-space editing tool for AutoDock Vina. It places the Vina search space directly on the molecular scene using the six values Vina consumes: center_x/y/z and size_x/y/z.

Stable-release scope: version 1.9.1 intentionally excludes experimental mouse drag-resizing. Use the numeric fields or the vinabox set command to edit the box.

Open the tool

Use Tools → Binding Analysis → Vina Grid Box, or:

vinabox showgui

Vina box geometry

The displayed box is defined directly from the Vina center and size:

minimum = center - size / 2
maximum = center + size / 2

The GUI's Exact box bounds section shows these minimum and maximum coordinates for X, Y and Z.

GUI controls

Center and Size

Enter center_x/y/z and size_x/y/z in Angstroms. New box creates or updates the 3D box with those values. Editing any field updates the displayed box.

From selection: choose a calculation method

Select the atoms the box should cover, choose a method, set Padding per side (Å), and click Create box from selection.

Selection bounds + padding (recommended)

This is the recommended method for receptor-pocket residues and arbitrary selected atom groups. It finds the minimum and maximum coordinates on each axis and expands both ends by the padding. The center is the midpoint between the expanded bounds; the size is the expanded maximum minus the expanded minimum.

minimum = min(coordinates) - padding
maximum = max(coordinates) + padding
center  = (minimum + maximum) / 2
size    = maximum - minimum

This directly contains all selected atoms and gives the requested padding on every face. It does not round dimensions to whole Angstroms or grid spacing; Vina performs its own map discretization when it reads the exported box.

Vina ligand-centroid method (ligands only; not recommended for receptor pockets)

This option mirrors Vina's ligand-derived box convention: it uses the arithmetic mean of the selected atom coordinates as the center, measures the furthest coordinate excursion from that center on each axis, adds padding to the half-dimension, doubles it, and rounds the dimension upward to an integer Angstrom value.

center = mean(atom coordinates)
size_axis = ceil(2 * (max(abs(coordinate_axis - center_axis)) + padding))

This option is provided for compatibility and comparison with Vina's ligand-derived convention. It is not recommended for receptor-pocket selections because the arithmetic mean may differ from the midpoint of the coordinate extrema, creating an offset or larger box than the tight padded bounding box.

Maintainer's note: Vina's source code documents what its centroid-based calculation does, but the maintainer has not found a clear published explanation in the source/documentation reviewed for why this convention was chosen over a minimum/maximum-centred padded bounding box. The bounds method is recommended here for receptor-pocket selection because it directly expresses the intended geometry. This is a use-case recommendation, not a claim that bounds-centering is universally superior for all Vina workflows.

Selection padding

Padding per side (Å) is added beyond every selected-coordinate extreme in the recommended bounds method. In the Vina ligand-centroid method, it is the buffer used by that calculation. The default is 4 Å. Changing padding while a selection-derived box is active recalculates the box using the active method. Editing center/size manually detaches the box from the stored selection coordinates.

Check selection

Check selection is a containment sanity check. It compares every selected atom against the current box and reports the number inside, the number outside, and the largest Cartesian overhang for atoms outside the box. It does not modify the box.

Show Vina rounded map extent

Vina discretizes the requested box dimensions using its grid spacing. With the usual 0.375 Å spacing, the internal voxel span is based on:

n = ceil(size / spacing)
real_span = n * spacing

The optional display shows this rounded internal span as a reference. It does not replace the requested size_* values exported to Vina.

View box

Frames the current box using ChimeraX's normal view command.

Copy Vina config

Copies a ready-to-paste configuration block to the clipboard:

center_x = 26.1720
center_y = 23.1697
center_z = -9.0871
size_x = 20.0000
size_y = 20.0000
size_z = 20.0000

Box color

Changes only the ChimeraX visualization color.

Clear

Removes the 3D Vina box from the scene. It does not modify the molecular models.

Command-line interface

The command is vinabox. The preferred GUI actions are showgui and hidegui. The aliases guishow and guihide are also accepted.

CommandEffect
vinabox set center X,Y,Z size X,Y,ZCreate or update the 3D Vina box
vinabox bounds padding 4Recommended: selected atom bounds plus per-side padding
vinabox centroid padding 4Vina ligand-centroid calculation; intended for ligand atoms
vinabox showguiShow the Vina Grid Box GUI
vinabox hideguiHide the GUI; the 3D box remains
vinabox reportPrint current center/size values
vinabox clearRemove the 3D Vina box

Examples:

vinabox set center 0,0,0 size 20,20,20
vinabox set center 26.1720,23.1697,-9.0871 size 20,20,20
vinabox bounds padding 4
vinabox centroid padding 4
vinabox report
vinabox showgui
vinabox hidegui
vinabox clear

ChimeraX's Float3Arg syntax requires each coordinate triple to be one comma-separated token. Use 0,0,0, not 0 0 0.

Backward compatibility: the older actions from-selection-bounds, from-selection-vina, show, and hide remain accepted. Use the shorter names above in new scripts.

Coordinate-system note

The selection-derived workflow currently uses ChimeraX atom scene coordinates. For a direct one-to-one Vina workflow, ensure the scene coordinate frame matches the coordinates in the receptor/ligand files that will actually be passed to Vina. Be especially careful if models have been translated or otherwise transformed at the scene/model level.

Scope and limitations

  • No docking is performed by this bundle.
  • No receptor or ligand PDBQT preparation is performed.
  • The stable public release does not include experimental drag-resize controls.
